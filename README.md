# Local workflow rehearsal

This synthetic fixture checks research infrastructure.
It is not another scientific trial and does not alter the completed study arms.

The installed DataLad 1.7.1 parser expects a commit message to begin with `[DATALAD RUNCMD]`.
Our fixture-only commit hook adds a Conventional Commit subject, a blank line, and freshly resolved Codex provenance.
The unmodified parser cannot recognize that record.
The rehearsal retains this failure and then tests a disclosed, process-local compatibility adapter.
The adapter supports only DataLad 1.7.1 and this exact leading-subject shape; it delegates all remaining parsing to DataLad and never edits installed code or history.

## Prerequisites

- Python 3, Git, Pixi, and direct `duct` CLI on `PATH`.
- A declared, installed Pixi environment providing DataLad 1.7.1 and git-annex.
  This module declares both in `pixi.toml` and `pixi.lock`.
  Run `pixi install --locked` before the rehearsal.
  The author check used the parent project environment with the same dependency lock; its exact path remains in that run's source receipt.
- An active Codex context for the exact commit-provenance resolver: `/Users/johnlee/.agents/skills/commit-provenance/scripts/resolve.sh`.
  Each fixture code commit invokes it afresh from a fixture-only `prepare-commit-msg` hook.
  Missing exact provenance stops execution.
- Git author identity already configured.
  No credentials or network are needed.

These paths are explicit CLI inputs, not bundled dependencies.
Receipt files record the script, manifest, lockfile, and resolver hashes.
This module does not modify global hooks, install packages, push repositories, or use Workshop.

## Run once

Run from this module in your own worktree.
Choose a new run ID for each justified execution; existing directories are never overwritten.
The same ID labels the outer duct capture, receipts, archives, and retained fixtures.

```bash
module="$PWD"
run_id="rehearsal-001"
duct -p "$module/logs/$run_id/run_" --fail-time 0 \
  --capture-outputs all --outputs all --record-types all \
  python3 "$module/rehearse.py" run \
  --run-id "$run_id" \
  --pixi-manifest "$module/pixi.toml" \
  --provenance-resolver \
  /Users/johnlee/.agents/skills/commit-provenance/scripts/resolve.sh
```

Use direct `duct` exactly once around the coordinator.
Do not nest capture wrappers.
Inspect a failed receipt before changing anything or launching a new run.
A run with nonzero status is retained, including empty streams.

## What is checked

1. Real `datalad create`, `save`, and `run` produce a deterministic sum/count JSON output stored in git-annex.
   Input and computation source remain in Git.
2. An independent clone at the pre-run commit has neither the generated path (including a broken symlink) nor an annex payload.
   Unmodified `rerun` fails to recognize the prefixed record.
   Its results are retained.
3. A second clean clone starts with the same absence checks.
   The explicit compatibility adapter performs real DataLad replay.
   Regenerated bytes must match a fixed independent oracle, and the recorded command must exit zero.
4. A successful no-op runs in a third clean clone.
   The same byte verifier must reject its missing output despite a zero command exit status.
5. A separate checkout initially lacks the annexed content, then retrieves it using `git annex get --from=local-transfer`.
   Its bytes must match.
   This is an explicit same-host local transfer, not public or cross-host distribution.
6. A peer Git worktree and the original checkout receive different tracked edits.
   Each checkout must retain its own file changes without affecting the other checkout's corresponding files.
7. A Git bundle retains the run history, annex symlink mode `120000`, and exact target.
   A tar archive retains fixture repositories, annex payloads, symlinks, and dirty worktree files.
   Bundles alone do not contain annex payloads; worktree administration in the tar retains local absolute paths.
8. Authored fixture code commits have Conventional subjects and exact Codex trailers.
   The resolver invocation evidence is retained for each commit.
   Git-annex's internal bookkeeping commits remain tool-generated metadata.

## Evidence and retention

`receipts/<run-id>/summary.json` reports the overall outcome; `checks.json`, `commands.json`, `native-replay.json`, and `compat-replay.json` provide individual evidence.
Numbered stdout/stderr files retain every subprocess stream, and `provenance.jsonl` records fresh resolver results.
`sources.json` identifies declared prerequisites.
Full outer duct metadata, stdout, stderr, resource samples, and its final summary remain under `logs/<run-id>/` after the process stops.

`archives/<run-id>/` contains the Git bundle and symlink-preserving tar; `artifacts.json` records their hashes.
Live fixture repositories remain under ignored `work/<run-id>/`.
Preserve that directory until the archive and receipts have been reviewed.
Do not recursively save these nested fixture repositories into the parent annex: retain history through the bundle/archive instead.

Commit source and receipts together, retaining complete duct records.
The module's storage policy places fixture archives in annex and leaves source, metadata and concise receipts in Git.
It must not describe the compatibility run as unmodified native DataLad or infer scientific quality, public availability, or complete worktree isolation from this fixture.

## Committing this module

Literal command output can itself look like an annex pointer.
The initial staging of `011.stdout` and `042.stdout` demonstrated that warning.
Their bytes and regular-file mode were preserved; `receipts/**` now disables the annex clean filter.
The coordinator also preserves Snapper and scopes the legacy annex pre-commit hook to the live `archives/` and `logs/` paths, using `hooks/annex-pre-commit`.
The original local legacy hook is backed up.
When installing hooks elsewhere, preserve existing hooks and compose this scoped annex step; do not overwrite an unrelated pre-commit hook.
